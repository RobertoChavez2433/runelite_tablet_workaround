## Mechanism

Both hot paths are in EXA (X server's 2D acceleration framework). `exaPutImage` is
X server's wrapper for PutImage that tries GPU migration, then falls back to
software (`fbPutImage`) when the destination pixmap is not in GPU memory. The
symptom pattern — same function offset at ~1600 calls/sec, always 22-row stride
— is the classic "EXA fell back to software pixmap" profile.

## Implications for Slice 3 (branch A: EXA)

Per plan: "Check whether exa_render.c / exa_accel.c is hitting the software
fallback. EXA has a migration mechanism that punts to software when pixmap isn't
in GPU memory. Force-GPU all WINDOW-backed pixmaps at allocation time."

This is the expected Slice 3 intervention: make the destination WINDOW pixmap
GPU-backed so exaPutImage's migration accepts GPU acceleration instead of
falling through to software.
